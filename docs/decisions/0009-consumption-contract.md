# 0009. The consumption contract: bytes on disk, document-only, obligations stated

## Status

Accepted.

## Context

Wake's snapshot format was documented as "a versioned public contract" without
the specification ever saying who was expected to read it, what Wake owed them,
or what they owed their own users. That gap had been papered over by naming a
particular downstream project; when that coupling was removed, the gap was
visible.

Four questions needed answering, and they depend on each other in that order.

## Decisions

### 1. The consumer is a separate program, in any language

Not a Go program importing Wake. Every package stays under `internal/`.

The alternative — exporting `event` and `snapshot` as a client library — was
rejected because it would turn every internal refactor into a semantic-version
decision on a project whose value is being small and boring, in exchange for
serving one language. The contract being the serialised form is also what made a
Python consumer implementable at the time this was tested.

A human at a terminal with `zstdcat` and `jq` is a first-class consumer too, but
that required no decision: it falls out of choosing JSONL.

### 2. Wake ships documentation and a fixture, and nothing else

No `wake export` subcommand, no client library, no machine-readable schema.

An export verb was considered and rejected on the grounds that it would mostly
duplicate `zstdcat` while tempting consumers to shell out to Wake — coupling
their pipeline to a CLI they do not control, which is a worse dependency than
the file format they were already reading.

A JSON Schema is **deferred, not refused**. The argument for it is real: the
prose contains 93 field definitions, and "did I implement this correctly?"
should be checkable rather than a matter of careful reading. The argument
against is that a schema is another artefact that can drift, needing its own
test to prove it matches. The trigger for revisiting is the existence of a
second independent consumer.

### 3. The compatibility promise is enforced mechanically

The versioning policy already existed in prose and referenced a `CHANGELOG` that
did not exist. Worse, the test guarding the format failed with *"fixture is
stale — regenerate it"* — an instruction that, followed literally, ships a
breaking change.

So: `CHANGELOG.md` now exists and carries the schema history, and the fixture
test names the fault instead of suggesting a workaround. It tells the developer
that this is a breaking change to a public contract, and asks which of two
things happened — a deliberate bump needing a changelog entry, or an accidental
change needing a revert.

A promise nobody can keep by accident is not a promise. This one is now
enforced by the same test run that enforces everything else.

### 4. Consumer obligations are stated normatively

Four requirements, in SPEC.md §6.3 and `docs/snapshot-format.md` §6: check
`schema_version`, ignore dot-prefixed directories, surface non-zero drops,
tolerate unknown fields and classes.

The third is the one that motivated writing them down. Wake counts every event
it loses at every boundary and reports the counts in each manifest. A consumer
that reads those counters and stays quiet converts an honest partial record into
a silent lie — the exact failure Wake exists to prevent, reintroduced one layer
up, and worse than no analysis because it carries the authority of kernel-level
evidence while missing part of it.

Wake cannot enforce any of this. Stating it establishes what "conforming" means
and tells a consumer author which shortcuts cost their users the truth.

## Consequences

- `internal/` stays internal. A Go consumer re-declares the handful of structs
  it needs, exactly as a Rust or Python one would. This is the intended cost.
- The reference fixture is load-bearing rather than illustrative, so it now
  exercises **all seven event classes** and reports a non-zero drop count. It
  previously covered three classes and reported no drops, which would have let a
  consumer pass its own tests without ever handling `generic` or seeing a
  snapshot that admits to losing anything.
- The fixture is regenerable with `make fixture` from a committed generator
  (`internal/snapshot/mkfixture`), which it was not before: the previous fixture
  documented itself as generated by a program that had never been committed.
- Adding an event class or a field is now a two-step change: make it, and decide
  whether it is additive. That friction is the point.
- This lands as SPEC.md §6 plus a new **M7**, rather than by widening M5. M5's
  criteria were met as written; retroactively broadening a completed milestone
  would make every other ✔ in that document untrustworthy.
